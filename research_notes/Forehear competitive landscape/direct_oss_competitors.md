# Direct open-source competitors to forehear (code-level teardown + fresh sweep, as of 2026-11-06)

Scope: open-source projects that run retrieval (or another speculative action) on interim/partial ASR transcripts while the user is still speaking, then validate or reuse the guess at end of turn. Forehear reference point (from this repo): Python, Apache-2.0, `Controller`/`Lookahead` runtime with policies `FinalOnly`, `EagerEndOfTurn`, `FixedInterval`, `StablePrefix`, `Adaptive`; validators `ExactMatch`, `TokenCoverage`, `ResultOverlap`; `ControllerStats` with `speculative_calls`, `cancelled_calls`, `reused_turns`, `accuracy`, `coverage`, `calls_per_turn`; Pipecat and LiveKit adapters in `src/forehear/integrations/`; offline benchmark on Vosk streaming traces of the human-recorded HeySQuAD dev questions (`data/README.md`); 60 tests and CI; not yet on PyPI (README installs from git).

Method note: GitHub repository search (~90 query variants, sorted by update), GitHub code search (10 queries on framework symbols such as `InterimTranscriptionFrame`, `EagerEndOfTurn`, `observe_partial`), PyPI JSON API by name, npm registry search, crates.io search, Hugging Face Spaces search, Hacker News (Algolia, since 2025-01-01) and web search. All repos below were shallow-cloned and read; nothing was executed. Star/fork/date figures come from the GitHub search API on 2026-11-06; commit/author counts come from `git log` on the clones (depth ≤300, so counts are complete for these small repos). The GitHub per-repo API (`/contributors`, `/issues`) was blocked in this session, so "contributors" = distinct git commit authors.

## 1. What does the full competitor set look like after a fresh sweep?

### Takeaway
There is still no mature, adopted, open-source library for speculative retrieval on interim ASR transcripts. The only project shaped like a reusable library with Pipecat+LiveKit adapters is **rohansx/primd** (3 stars, one author, inactive since 2026-05-14, benchmark on random bit vectors). Everything else is hackathon or take-home code (overhear, hhgoa2, the Samsung PRISM "Streaming Live RAG" cluster, the two "Zero-Latency Voice RAG" repos), between-turn prefetch (Salesforce VoiceAgentRAG), speculative *generation* rather than retrieval (precog, specvoice, pipecat-speculative-prefill), a name placeholder (premove on PyPI), or a sub-feature of a much larger engine (oneiron).

## 2. rohansx/primd: the closest library-shaped competitor

### Takeaway
primd is the only competitor with the same architecture as forehear: `observe_partial` → `finalize`, plus Pipecat and LiveKit adapters and published packages. In practice it is a solo project dormant for about 6 months. Its "100% speculative cache hit rate" comes from a synthetic benchmark of random 256-bit vectors, which its own report says is "a workload property". It has no stale-guess cancellation (it doesn't need one because scans take microseconds), it validates with one hard-coded Hamming threshold, it measures no waste, and its LiveKit adapter hooks event names that current LiveKit Agents doesn't emit.

### Cited Findings
- Repo metadata: owner Rohan (GitHub `rohansx`; `rohan@primd.dev` / `hello@rohan.sh`). Rust core plus Python adapters. 3 stars, 0 forks, 0 open issues. Created 2026-05-01, last push 2026-05-14. 41 commits, all by one author (first commit dated 2026-04-24). The last commit, on 2026-05-14, is "chore: update Cargo.lock for primd-dwm in cli deps" — [GitHub repo](https://github.com/rohansx/primd)
- License is inconsistent. `Cargo.toml` and the README say Apache-2.0, but the repo has no LICENSE file, so GitHub reports no license — [Cargo.toml](https://github.com/rohansx/primd/blob/main/Cargo.toml)
- Packages: `pipecat-primd` 0.1.0 on PyPI (uploaded 2026-05-05). pepy shows 890 total downloads; pypistats shows 8 last month and 4 last week. `livekit-primd` isn't on PyPI even though the README lists it under "v0.3 — shipped". `primd-core` (89 downloads) and `primd-cli` (17) are on crates.io — [PyPI](https://pypi.org/project/pipecat-primd/), [pepy](https://pepy.tech/project/pipecat-primd), [crates.io](https://crates.io/crates/primd-core)
- Positioning: "the predictive turn-cache for real-time conversational AI … starts retrieving while the user is still speaking, predicts the next turn during TTS playback, and serves repeats from a sub-microsecond cache". Description: "open-source VoiceAgentRAG" — [README](https://github.com/rohansx/primd/blob/main/README.md)
- Core API in `primd-core/src/query_context.rs`: `QueryContext::observe_partial(&mut self, index, partial: BinarySignature, top_k)`, `finalize(&mut self, index, final_sig, top_k) -> QueryOutput`, `warm_next(&mut self, index) -> Vec<EventId>`, `reset_utterance()`, `with_predictor`, `with_cold_tier`. Results are tagged `ServedBy::{Speculative, DeltaCache, ShardScan, FullScan}`. The HTTP API exposes `/session/{id}/observe`, `/session/{id}/finalize`, `/session/{id}/warm`, `/query`, and an OpenAI-shaped `/v1/chat/completions` — [query_context.rs](https://github.com/rohansx/primd/blob/main/primd-core/src/query_context.rs), [README](https://github.com/rohansx/primd/blob/main/README.md)
- Trigger: every STT partial goes through a `StreamingQuery` "drift gate", which re-scans only when the partial's binary signature differs from the last emitted one by at least `drift_threshold` bits (suggested range 12–32 of 256). Counters are `updates_received`, `updates_emitted`, `updates_suppressed`, and `emit_rate()` — [streaming.rs](https://github.com/rohansx/primd/blob/main/primd-core/src/predict/streaming.rs)
- Validation and reuse: `finalize` returns the cached speculative top-K only if `spec.hamming_distance(&final_sig) <= 16 && cached.len() == top_k` (16 is a literal in code). Otherwise it tries a fuzzy "predictive-coding delta cache" keyed on scope hash, then a scoped or full SIMD scan. There is no async cancellation: `observe_partial` runs the scan synchronously (~108 µs p50 per the README) — [query_context.rs](https://github.com/rohansx/primd/blob/main/primd-core/src/query_context.rs), [cache.rs](https://github.com/rohansx/primd/blob/main/primd-core/src/predict/cache.rs)
- Extra layers forehear lacks: a Markov / Successor-Representation next-turn predictor (`warm_next` during TTS), event-scoped shards, a WASM target, and a "DWM cold tier" — [README](https://github.com/rohansx/primd/blob/main/README.md)
- Retrieval primitive: 256-bit binary signatures with SIMD Hamming scan (AVX-512 / AVX2 / scalar). Embedders: `hashed`, local `fastembed` (bge-small-en-v1.5), OpenAI. The README says binary signatures "trade some recall for speed" and that primd "hands off to your existing vector DB" for recall-sensitive workloads — [README](https://github.com/rohansx/primd/blob/main/README.md), [embed/local.rs](https://github.com/rohansx/primd/blob/main/primd-core/src/embed/local.rs)
- Headline claim: `finalize` p50 1.6 µs vs 157.8 µs naive ("98× faster"), and "100% speculative-cache hit rate on this workload". "Reproducible: `cargo bench --bench voice_session`" with "200 utterances over 20 canonical intents, 4 partial transcripts per turn, 100k-doc corpus across 50 events" — [README](https://github.com/rohansx/primd/blob/main/README.md)
- The benchmark is fully synthetic, not speech and not even text. `voice_session.rs` builds the corpus from `random_sig()` (random 32-byte vectors) perturbed by 30 bits, and builds "partials" by perturbing the final signature with `PARTIAL_DRIFTS: [u32; 4] = [30, 12, 6, 2]` bits — [voice_session.rs](https://github.com/rohansx/primd/blob/main/primd-bench/benches/voice_session.rs)
- The project's own bench report concedes this: "100 % speculative hit rate is a workload property. Synthetic intents drawn from 20 canonical clusters with low Hamming drift make speculation trivially correct. Real voice workloads … will see lower hit rates"; and "The synthetic workload is too easy" — [bench-report.md](https://github.com/rohansx/primd/blob/main/docs/benchmarks/bench-report.md)
- Pipecat adapter `pipecat_primd.retriever.PrimdRetriever(FrameProcessor)`: `InterimTranscriptionFrame` → `_observe` (HTTP `/observe`), `TranscriptionFrame` → `_finalize`, `BotStartedSpeakingFrame` → `_warm`. It injects context with `LLMMessagesAppendFrame` pushed `UPSTREAM`. The docstring says "Tested against Pipecat 0.0.49+". It needs the separate Rust `primd serve` process — [retriever.py](https://github.com/rohansx/primd/blob/main/pipecat-primd/pipecat_primd/retriever.py)
- LiveKit adapter `livekit_primd.PrimdRetriever` plus `attach_to_voice_assistant(assistant, retriever)` subscribes to `"user_speech_committed"`, `"user_speech_interim"`, `"user_started_speaking"`, `"agent_started_speaking"`, and logs failures to attach only at debug level — [livekit retriever.py](https://github.com/rohansx/primd/blob/main/livekit-primd/livekit_primd/retriever.py)
- Current LiveKit Agents (main, cloned 2026-11-05) emits `"user_input_transcribed"` for transcripts. A grep found no `user_speech_interim` or `user_speech_committed` in the codebase — [livekit/agents voice/events.py](https://github.com/livekit/agents/blob/main/livekit-agents/livekit/agents/voice/events.py)
- Tests and CI: GitHub Actions runs `cargo fmt --check`, `cargo clippy -D warnings`, `cargo test --workspace`. There are 161 Rust `#[test]` functions and 12 Python test functions in the two adapter packages — [ci.yml](https://github.com/rohansx/primd/blob/main/.github/workflows/ci.yml)
- Docs are extensive: architecture per layer, tech spec, benchmark protocol, and business docs (competitive landscape, GTM, strategy). primd's own competitor list names only Moss/InferEdge (closed source), Salesforce VoiceAgentRAG, StreamRAG (Meta+CMU paper) and ContextCache (paper) — [competitive-landscape.md](https://github.com/rohansx/primd/blob/main/docs/business/competitive-landscape.md)

### Inferences
- Maturity rating: **early prototype, dormant**. It's well engineered for one person (CI, clippy, many tests, docs), but has no external users visible (3 stars, about 8 PyPI downloads a month), no commits for about 6 months, and no real-speech evaluation.
- Its LiveKit adapter very likely attaches nothing on LiveKit Agents 1.x. `_attach` swallows the failure, so users get silent no-ops. Forehear can claim working LiveKit 1.x integration if its adapter targets `user_input_transcribed`. That needs live verification.
- primd's Hamming ≤16 validator is the only validator it has, and its threshold has never been tested on real ASR revisions. Forehear's validator sweep on real Vosk interims is a direct, defensible point of difference.
- primd competes on raw retrieval microseconds and next-turn prediction. Forehear competes on correctness under real ASR revisions and on waste accounting. These positions can coexist; primd could even serve as a fast retriever behind forehear.

### Gaps
- Not verified whether `pipecat-primd` works on current Pipecat (frame names exist in current Pipecat `frames.py`, but the adapter wasn't run).
- The pepy total (890) likely includes mirror and bot downloads; real install count unknown.

## 3. nikhilesh9ix/overhear: the closest hackathon design (honestly measured)

### Takeaway
overhear implements nearly the same loop as forehear: retrieve on interims, cancel stale, accept or reject on the final, count hits. It reports an honest **0.318 hit rate over 22 spoken queries**. But it is a single-day hackathon app with no license, no tests, no adapters and no package, and its "spoken" queries are TTS-synthesized.

### Cited Findings
- Metadata: owner Kuppili Nikhilesh Raju (`nikhilesh9ix`). Python. **No license file**. 0 stars, 0 forks. Created 2026-08-22. 11 commits, all on 2026-08-22, one author. Built for "Hacker House Goa, Task #2. `#RAGInGoa`" — [GitHub repo](https://github.com/nikhilesh9ix/overhear), [README](https://github.com/nikhilesh9ix/overhear/blob/master/README.md)
- API: `app/core/retriever.py` defines `SpeculativeRetriever(index, embedder, top_k)` with `on_partial(text)`, which cancels the previous `asyncio` task (`self._task.cancel(); self.cancelled += 1`) and launches `_speculate`; `on_final(text) -> RetrievalOut` ("The critical path. Returns immediately on a speculation hit"); `reset()`; and `stats()`, which returns `cancelled`, `hits`, `misses`, `hit_rate` — [retriever.py](https://github.com/nikhilesh9ix/overhear/blob/master/app/core/retriever.py)
- Trigger: Sarvam `saaras:v3-realtime` interim transcripts, "embed those partials on a debounce". Validation: `_key_accepts` accepts a speculation if the cached query is a word-prefix covering ≥ `speculation_prefix_coverage` = 0.8 of the final — [README](https://github.com/nikhilesh9ix/overhear/blob/master/README.md), [retriever.py](https://github.com/nikhilesh9ix/overhear/blob/master/app/core/retriever.py)
- Measured results. Prefix study over 74 golden queries: at 60% prefix coverage, gold R@5 falls 0.960 → 0.730; at 80%, 0.960 → 0.919. Voice mode: "22/22 completed … Speculation hit rate **0.318**". Their finding: "Sarvam's interim transcripts are revised, not merely extended". Fixing a blocking bug in `on_final` "moved voice T1 P50 from 535ms to 490ms and the hit rate from 0.167 to 0.333" — [README](https://github.com/nikhilesh9ix/overhear/blob/master/README.md)
- Speech source: the bench audio is TTS. `scripts/make_bench_audio.py` says "Synthesize spoken versions of golden queries with Sarvam TTS … Using TTS rather than human recordings is a stated limitation: it removes accent, background noise and disfluency" — [make_bench_audio.py](https://github.com/nikhilesh9ix/overhear/blob/master/scripts/make_bench_audio.py), [bench/audio/MANIFEST.txt](https://github.com/nikhilesh9ix/overhear/blob/master/bench/audio/MANIFEST.txt)
- Integrations: its own FastAPI WebSocket app (`app/ws.py`); no Pipecat or LiveKit imports; no `tests/` directory; no CI; not on PyPI (the `overhear` PyPI name belongs to an unrelated placeholder) — [repo tree](https://github.com/nikhilesh9ix/overhear), [PyPI overhear](https://pypi.org/project/overhear/)

### Inferences
- Maturity: **hackathon demo, abandoned**. Its value to forehear is as independent confirmation of forehear's thesis: on real streaming ASR, interims get revised, naive reuse fails, and validator choice decides the quality-latency trade-off. Its n=22 TTS result is much weaker evidence than a large human-speech benchmark.

### Gaps
- No issues or discussion to gauge reception; 0 stars suggests none.

## 4. SalesforceAIResearch/VoiceAgentRAG: between-turn prefetch, not interim speculation

### Takeaway
VoiceAgentRAG is the most visible project in the space (161 stars, an arXiv paper), but it predicts *follow-up* questions after a finalized turn and pre-fills a semantic cache. It does not use interim transcripts, does not cancel stale guesses, has no Pipecat or LiveKit adapters, and its licensing is contradictory (Apache-2.0 LICENSE file vs a CC-BY-NC-4.0 README).

### Cited Findings
- Metadata: Salesforce AI Research; commits by Jielin Qiu plus "Salesforce OSPO Service Bot". Python. 161 stars, 29 forks, 0 open issues. Created 2026-03-02. 6 commits; the last, on 2026-06-02, is "Upload required SECURITY.md file for compliance". Paper: arXiv 2603.02206 — [GitHub repo](https://github.com/SalesforceAIResearch/VoiceAgentRAG), [arXiv](https://arxiv.org/abs/2603.02206)
- License conflict: `LICENSE.txt` is "Apache License Version 2.0 … Copyright (c) 2024 Salesforce, Inc." and GitHub reports Apache-2.0, but the README badge and License section say "licensed under CC-BY-NC-4.0" — [LICENSE.txt](https://github.com/SalesforceAIResearch/VoiceAgentRAG/blob/main/LICENSE.txt), [README](https://github.com/SalesforceAIResearch/VoiceAgentRAG/blob/main/README.md)
- Package `voice-optimized-rag` 0.1.0 (`pyproject.toml`) is not on PyPI — [pyproject.toml](https://github.com/SalesforceAIResearch/VoiceAgentRAG/blob/main/pyproject.toml)
- API: `MemoryRouter` (`start`, `stop`, `query`, `query_stream`, `ingest_directory`, `ingest_texts`, `metrics`, `cache`), `SlowThinker` (`_on_user_utterance`, `_on_silence`, `_on_topic_shift`, `_on_priority_retrieval`, `_predict_followups` via LLM or keywords), `FastTalker.respond/respond_stream`, `SemanticCache` (FAISS; `get`, `put`, `clear_stale`, TTL and LRU eviction), and a `ConversationStream` event bus — [voice_optimized_rag/core](https://github.com/SalesforceAIResearch/VoiceAgentRAG/tree/main/voice_optimized_rag/core)
- Trigger: `MemoryRouter.query(text)` publishes a `USER_UTTERANCE` event for the complete user query. The Slow Thinker then predicts follow-ups and pre-fetches them. Nothing consumes interim or partial transcripts — [memory_router.py](https://github.com/SalesforceAIResearch/VoiceAgentRAG/blob/main/voice_optimized_rag/core/memory_router.py)
- Claims: "200 queries across 10 diverse conversation scenarios on Qdrant Cloud", "75% cache hit rate (86% on warm turns 5-9)", "316x retrieval speedup (110ms → 0.35ms)". The benchmark drives typed `SAMPLE_CONVERSATIONS` text through the router, not speech — [README](https://github.com/SalesforceAIResearch/VoiceAgentRAG/blob/main/README.md), [examples/benchmark.py](https://github.com/SalesforceAIResearch/VoiceAgentRAG/blob/main/examples/benchmark.py)
- 32 tests (`tests/`); no `.github` CI directory; no Pipecat or LiveKit imports (it ships its own Whisper STT and Edge TTS wrappers) — [tests](https://github.com/SalesforceAIResearch/VoiceAgentRAG/tree/main/tests)

### Inferences
- Maturity: **research artifact, static** since its June compliance commit. It complements forehear rather than duplicating it: it hides retrieval *across* turns, forehear *within* a turn. Its 75% hit rate is not comparable to forehear's within-turn reuse rate.
- The license contradiction is a real adoption barrier for commercial users, and it's a fair, evidence-backed point for forehear's Apache-2.0 positioning.

### Gaps
- Which license Salesforce intends is unknown; there's no issue on the topic (0 open issues).

## 5. The "Zero-Latency Voice RAG" pair (yashkum2014, Jasleen-05)

### Takeaway
Two near-identical take-home-style repos (same "CCaaS … technical manuals … sub-800ms TTFB" brief). One simulates ASR with hard-coded strings. The other cancels stale tasks but reuses in-flight speculation without checking it against the final query. Neither is a competitor in any practical sense.

### Cited Findings
- yashkum2014/zero-latency-voice-rag: Yash Kumar, MIT, 0 stars. Created 2026-01-28, last push 2026-02-24. 8 commits, one author. README: "Streaming ASR produces partial transcripts … RAG pre-fetch begins as soon as partial ASR output is available" — [README](https://github.com/yashkum2014/zero-latency-voice-rag/blob/main/README.md)
- Its "streaming ASR" is a generator over three hard-coded strings ("How do I reset the router", …). `main.py` calls `hybrid_search`, `llm_stream`, `stream_tts` and `rerank` synchronously for every partial. There is no cancellation, no validation, and no tests — [asr_stream.py](https://github.com/yashkum2014/zero-latency-voice-rag/blob/main/asr_stream.py), [main.py](https://github.com/yashkum2014/zero-latency-voice-rag/blob/main/main.py)
- Jasleen-05/Zero-Latency-Voice-RAG-for-Technical-Manuals: Jasleen Kaur (Matharoo), MIT, 0 stars. Created 2026-01-29. 4 commits, all on 2026-01-30. Whisper ASR, Qdrant + BM25 + cross-encoder, Piper TTS. It commits `__pycache__`, a local Qdrant DB and Piper models — [GitHub repo](https://github.com/Jasleen-05/Zero-Latency-Voice-RAG-for-Technical-Manuals)
- `backend/speculative.py`: `SpeculativeRAG.start(query)` cancels the previous `asyncio.Task` and starts `run_rag(query)`. `finalize(query)` returns `await self.current_task` if that task is still running, without comparing its query to the final query; otherwise it re-runs `run_rag(query)`. So a finished speculation is never reused — [speculative.py](https://github.com/Jasleen-05/Zero-Latency-Voice-RAG-for-Technical-Manuals/blob/main/backend/speculative.py)

### Inferences
- Maturity: **student/assignment code**. The Jasleen-05 `finalize` logic gets it backwards: it reuses unvalidated in-flight guesses and throws away completed ones. That's a concrete example of the correctness bugs forehear's validator layer prevents.

### Gaps
- The source of the shared brief (interview assignment vs course) is unconfirmed.

## 6. Speculative *generation* neighbors: precog, specvoice, premove, pipecat-speculative-prefill

### Takeaway
These speculate the LLM response, TTS audio or KV-cache prefill on interims, not retrieval. They're adjacent competitors for the same latency budget and could be combined with forehear. None ships a retrieval-validation layer. premove is the only one whose stated roadmap includes RAG prefetch, but its published package is an empty placeholder.

### Cited Findings
